# 替换走路人物

仅在用户选择“人物领走”或“文字领走”后执行本流程。其余样式不询问人物，不读取或保存人物记录。

1. 用户已为本次明确指定人物时，优先使用本次选择。
2. 否则运行 `py -X utf8 "<SKILL>/scripts/personal_characters.py" show`。返回个人默认人物时，告知“本次沿用你上次确认的人物：<名称>”，继续制作，不再次索图或生成人物。返回 null 才表示未保存过；素材缺失或记录损坏不视为没有，向用户说明并补齐，不能静默替换。
3. 没有个人默认人物时，询问：“你有没有想用的自定义人物图？有的话发给我；没有的话就用样片里的默认人物。”明确没有或选择内置时复用黄头巾人物；未回复不能当作没有。
4. 有新人物图时，先生成符合尺寸规则的走路效果并让用户确认；已有合格动作帧时直接预览确认。确认后保存个人素材及配置，默认作为以后使用的人物，不因对话结束而丢失。用户明确只用于本次时保留旧默认。

### 本机保存与复用

个人素材保存在**执行脚本所属的本机 Skill 安装目录**的 `user-data/characters/`。它是用户专用子目录，不是公共 `assets/characters/`，也不是给 SKILL.md 追加用户信息。`default.json` 指向当前默认人物；每个人物单独目录，保留原图（用户提供时）、透明动作帧、名称、步频、尺寸比例和确认状态。原输入文件移动或删除后，已保存动作仍能独立使用。

```powershell
py -X utf8 "<SKILL>/scripts/personal_characters.py" save --config "<已确认动作的character.json>" --name "我的人物" --source "<用户原图>" --confirmed
py -X utf8 "<SKILL>/scripts/personal_characters.py" show
```

`--confirmed` 只能在用户实际确认人物效果后使用，不能用技术检查代替确认；已有动作帧但没有原图时省略 `--source`。用户明确仅本次使用时增加 `--this-time-only`，保存素材但不更改原默认。旧人物目录保留，不覆盖或删除。

正式生成时，带人物样式在未指定 `characterFrames` 的情况下会自动复用本机个人默认人物；显式 `characterFrames` 优先。如用户本次要求使用内置人物，配置 `characterPreset: "builtin"`，不会覆盖个人默认。公共 Playground 样片始终使用内置人物，不读取用户个人素材。

`user-data/` 已被 `.gitignore` 忽略，禁止强制添加、上传 GitHub、打包进公开发布文件，或将个人图复制到公共 assets。更新 Skill 保留本机 `user-data/`；需要重装或更换目录时，先原样备份并迁移该目录。不同电脑或不同 Agent 的安装目录不会自动共享人物，需要用户自行迁移个人目录。

需要从静态图生成新动作时使用可用的 imagegen Skill/内置图片工具，不编造一个可以自动让任意上传图片走路的确定性接口。身份参考优先，透明背景和全身完整，4×2 共 8 帧可作为初始动作测试；必要时增加到 12～16 帧。脸、发型、衣服、配饰和用户要求的文字都应保持一致，未保留时如实说明。

生成要求：同一人物朝右、同一视角、同一尺度；每格在本地相同位置原地迈步，不逐格向右平移；双腿交替完成接触、下压、经过、抬升，最后接回首帧；全身和脚不裁切，格子之间有透明留白，无文字编号、网格或棋盘格。人物前进由程序控制，不画进每张动作图。

生成后检查 alpha，再提取：

```powershell
py -X utf8 "<SKILL>/scripts/prepare_character.py" --sheet "<透明动作图.png>" --columns 4 --rows 2 --out "<新人动作目录>"
```

输出 `character.json` 中的 `characterFrames` 可放进正式渲染配置。提取程序只检查透明与边界，不证明动作自然。按顺序循环播放检查身份变化、尺度跳变、头部抖动、脚部穿插和循环接缝，不把静态图平移冒充迈步。

渲染默认保持人物完整高度等于条高，身体向下放，在填充前沿领走；条外最多半个条高，起点和终点人物都完整显示。保留原始图与动作帧，不在换人物时改动进度条样式。
